# Maskey

The owner, as `mk` help and hints call them, is the user you work for: the credentials are theirs, kept in their iCloud Keychain or in a Bitwarden Secrets Manager project they connected, and only they can approve a change to program access. `mk run` masks the ordinary credential values it puts in the child's environment. For an SSH Key entry it supplies a public key and a signing agent. Never ask the owner to paste a credential into the conversation, put one in a command line, or write one to a file.

Syntax is in `mk --help` and `mk <command> --help`; error kinds and exit statuses in `mk help exit-codes`. Follow the error's `mk: hint:` line or JSON `recovery`. If a batch stops, keep the completed writes and check any uncertain write before repeating it. `mk run --json` keeps masked child output and structures Maskey's own errors.

## Use a credential

1. Use the store the owner named. If the store is unknown, use `mk store list` to see the connections. Resolve an ambiguous store before using or changing a same-named entry. To find a reference, list the intended store with `mk list --store <name>`, adding the namespace if known. Use the exact, case-sensitive reference shown. Add `--json` when kind or program access matters.
2. Wrap the command that needs the credential, not a shell you keep or a whole agent, and give it only the entries it needs: in a store called `work`, `mk run --store work github/GITHUB_TOKEN -- gh pr list` selects one entry. `mk run --store work github -- gh auth status` selects the whole namespace. List several selectors before `--`; an entry you name wins over the same NAME from a namespace.
3. `mk run` starts the command without a shell. When it needs a variable expanded, quote the script in single quotes so the variable expands in the child, where it is set, and pass the value on stdin rather than in an argument, which other processes can see: `mk run --store work api/API_TOKEN -- sh -c 'printf "Authorization: Bearer %s\n" "$API_TOKEN" | curl -H @- https://api.example.com'`. In double quotes your own shell expands it first, where it is unset or holds something else.
4. An exact match for an ordinary credential in the command's output appears as a marker such as `***`. Masking covers stdout and stderr only, so do not run commands that print values in another form (base64, URL-encoded, hex dumps, debug logs) or insert line breaks or styling within them on a terminal.

Entries live in a store: `icloud`, or a Bitwarden project the owner added under a name of their choice. An entry command works on this Mac's default store unless `--store <name>` names another, and looks nothing up in a second one. Carry the selected `--store` into every read and write. For `mk run`, place it before the first selector. In configuration that outlives the task, such as a script or a program's `mk get` helper, name the entry's store with `--store`, so that it keeps working when the owner changes the default. Only the owner adds a store or replaces its token. Ask them to run `mk store add bitwarden` or `mk store token <name>` in their terminal to enter the access token at its hidden prompt. Change the default or remove a store only when the owner asks. The `mk store remove` confirmation applies to the connection the name had when it asked. With `--yes`, removal acts on whichever connection has that name when the command runs. Removing a store clears its access token, program access, and saved copy from this Mac. Its entries stay in Bitwarden.

A program configured to run a command for its key, such as Claude Code's `apiKeyHelper`, can run `mk get --store <name> <namespace>/<NAME>`. Success writes the raw value to stdout even with `--json`. Configure the consumer to run it; never run `mk get` yourself, since its output would enter the conversation. If it fails with `not_granted`, the owner has not granted the entry program access: use `mk run`, and ask the owner to grant it only when a program must read the value from stdout. Never run `mk grant` or `mk revoke` yourself. A recent CLI approval can let them change access without asking the owner again.

An `ssh` entry is an SSH private key the command never receives: `mk run` sets its NAME to the public key and signs with the private key through an agent at `SSH_AUTH_SOCK` until the command ends. Wrap the command that connects or signs, such as `mk run --store work deploy/DEPLOY_SSH_KEY -- git push`, and select only the keys it needs, since a server counts each key offered as one authentication attempt. Do not add `-A`, which lends the keys to the remote host. When `ssh_config` sets `IdentityAgent`, which takes precedence, pass `-o IdentityAgent=SSH_AUTH_SOCK` to `ssh`, or `-c core.sshCommand='ssh -o IdentityAgent=SSH_AUTH_SOCK'` to `git`, whose own `-o` means something else. For an SSH commit signature, give Git the public key rather than a key file: `mk run --store work signing/SIGNING_SSH_KEY -- sh -c 'git -c gpg.format=ssh -c user.signingKey="key::$SIGNING_SSH_KEY" commit -S -m "<message>"'`. If `mk run` reports that the key is protected by a passphrase, ask the owner to import it in their terminal using the hint and the same `--store`. The import stores the key without its passphrase.

A `pem` entry is a private key a program reads itself, as a variable or on stdin inside `sh -c`. For SSH or Git, ask the owner to switch an unprotected key to SSH Key in the window, or import a protected key from its source into an SSH Key entry in their terminal. Leave key loading to `mk run`. If the program accepts only a file path, tell the owner instead of writing the key to disk. A program that reads the key's passphrase from a variable, such as Snowflake's `PRIVATE_KEY_PASSPHRASE`, takes it from another entry of the namespace.

When the owner asks what used a credential, `mk activity` shows which programs got, read, or changed which entries on this Mac, without values. Use `mk activity --store <name> <namespace>/<NAME>` for a specific store and entry, including after the store is removed.

## Store or change a credential

- For a single-line value, ask the owner to run `mk set --store <name> <namespace>/<NAME>` in their terminal. The prompt hides the input and asks before replacement. For multiline input, have the owner use the window or redirect an existing source file into `mk set --store <name> --stdin <namespace>/<NAME>`.
- Pipe a producer directly into `mk set --store <name> --stdin <namespace>/<NAME>`. This replaces without confirmation. A one-line value loses its final line ending; a value of several lines, such as a PEM key, is stored byte for byte, unless the owner removes an SSH key's passphrase at the prompt `mk set` shows on their terminal. A new entry whose name ends in `SSH_KEY` gets kind `ssh`. Only the owner changes an existing entry's kind, in the window.
- `mk rename --store <name> old/NAME new/NAME` keeps the value, kind, notes, and program access. Run `mk delete --store <name> --yes <namespace>/<NAME>...` only for entries the owner asked to delete. An iCloud deletion reaches Macs syncing that Keychain. A Bitwarden deletion moves the entry to trash for the shared project.
- Only when the owner asks to uninstall Maskey, quit the app and run `mk uninstall --yes`. Keep the app until cleanup succeeds. On failure, follow the recovery hint, which gives the executable path if the `mk` link was removed. Entries stay in their stores.
